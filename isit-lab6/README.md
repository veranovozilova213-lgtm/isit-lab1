# **Лабораторная работа №6**



### **Разработка серверной части приложения**



#### **Цель работы**



Изучить основы разработки серверной части веб-приложений на PHP, создать структуру проекта, реализовать маршрутизацию HTTP-запросов и разработать контроллеры для обработки запросов пользователей.



#### **Краткое описание выполненного задания**



На основе архитектуры системы «Приложение доставки заказов» (лабораторные работы №3–5) создана основа серверной части приложения на PHP 8.2 по паттерну MVC: единая точка входа, собственный маршрутизатор, три контроллера, модели и HTML-шаблоны. Сервер отвечает страницами: главная со сводкой, список заказов с фильтром, просмотр заказа, форма создания, список курьеров и карточка курьера.



Данные хранятся в JSON-файлах (`storage/`), работа с ними вынесена в модели. База данных будет подключена в следующих работах: контроллеры и шаблоны при этом менять не потребуется.

#### **Описание механизма маршрутизации**



Все запросы направляются в public/index.php (front controller). Он подключает автозагрузку и вспомогательные функции, создаёт Router, загружает таблицу маршрутов routes/web.php и передаёт маршрутизатору метод и адрес запроса.



**Таблица маршрутов:**



|**Метод**|**Адрес**|**Контроллер и метод**|**Назначение**|
|-|-|-|-|
|GET|/|HomeController::index|главная страница (сводка)|
|GET|/tasks|TaskController::index|список заказов (фильтр ?status=)|
|GET|/tasks/create|TaskController::create|форма создания заказа|
|POST|/tasks|TaskController::store|приём формы создания|
|GET|/tasks/{id}|TaskController::show|просмотр деталей заказа|
|GET|/projects|ProjectController::index|список курьеров|
|GET|/projects/{id}|ProjectController::show|карточка курьера|





**Алгоритм:**



1\. Из адреса `/tasks/5?status=done` выделяется путь `/tasks/5`.

2\. Маршруты просматриваются по порядку. Пропускаются маршруты с другим методом.

3\. Для маршрута с подходящим методом метод `match()` превращает шаблон `/tasks/{id}` в регулярное выражение и возвращает параметры (`\\\['id' => '5']`) или `null`, если адрес не подошёл.

4\. Для подошедшего маршрута создаётся объект контроллера, и вызывается его метод, а параметры из адреса передаются как именованные аргументы (`show(string $id)`).

5\. Если подходящего маршрута нет, возвращается страница 404 с кодом ответа 404.



Порядок регистрации важен: маршрут `/tasks/create` зарегистрирован выше `/tasks/{id}`. Иначе слово `create` было бы принято за номер заказа.



Ошибки выполнения исключения) перехватываются в `public/index.php`: приложение возвращает код 500 и страницу ошибки. Подробный текст ошибки показывается только при `debug = true` в `config/app.php`.









#### **Описание реализованных контроллеров**



|**Контроллер**|**Метод**|**Что делает**|
|-|-|-|
|HomeController|index|считает заказы по статусам и количество курьеров, показывает главную страницу|
|TaskController|index|список заказов; при ?status=done оставляет только выбранный статус|
|TaskController|show($id)|карточка одного заказа (курьер, адрес, сумма); если заказа нет — страница 404|
|TaskController|create|форма создания нового заказа|
|TaskController|store|читает $\_POST, проверяет данные на сервере; при ошибках показывает форму с подсказками и кодом 422, иначе сохраняет заказ и перенаправляет на /tasks (код 302)|
|ProjectController|index|список курьеров|
|ProjectController|show($id)|карточка курьера; если курьера нет — страница 404|



**Передача данных между слоями:**



маршрутизатор → контроллер: параметры адреса (`{id}`) как аргументы метода;

запрос → контроллер: `$\\\_GET` (фильтр по статусу) и `$\\\_POST` (данные формы заказа);

контроллер → шаблон: функция `view('tasks/show', \\\['task' => $task, ...])`, ключи массива становятся переменными в шаблоне;

модель → контроллер: массивы данных (`all()`, `find()`, `add()`).



Все значения в шаблонах выводятся через функцию `e()` (`htmlspecialchars`), поэтому внедрить HTML-код через название заказа или адрес доставки невозможно (проверено на строке `<script>alert(1)</script>`).
